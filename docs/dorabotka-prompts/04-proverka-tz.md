КРИТЕРИИ

Один прогон
- В README есть один путь: текст о компании и человеке → черновик полями → решение ждать подтверждения → одна стоимость. Остальные экраны для этого пути не обязательны.

- Боевой режим: один облачный запрос, стоимость из уже существующей таблицы цен CostTracker. Неудачный запрос не подменяется удачным черновиком; остаётся ошибка этого шага.
- Подтверждение человека включено. Кнопки и команды, которая отправляет письмо по этому пути, нет.

Проверка поиска
- Есть набор учебных вопросов. Для каждого заранее известно, какой фрагмент должен найтись и какой к вопросу не относится.
- Проверка проходит, только когда нужный фрагмент есть в выдаче, а чужой нет.
- Пустой набор вопросов даёт явный отказ «набор пуст», не зелёный успех и не молчание.
- Пустая выдача по вопросу с известным фрагментом — ошибка проверки.
- Это сравнение выдачи. Отдельной модели пересортировки нет.
- Учебные векторы — хеши. Токены на проверку не тратятся.

Повтор внешнего вызова
- Отказ «слишком много запросов» (429) не выглядит успехом шага.
- В попытке видны: сколько раз уже пробовали, текст последней ошибки, когда можно пробовать снова.
- Повтор того же вызова обновляет эту запись, а не рисует новый независимый успех задним числом.
- Успех с первой попытки не показывает прошлые ошибки, которых не было.
- Успех после реальных отказов не стирает счётчик и последнюю ошибку так, будто отказа не было.
- В проверке живой сервис не вызывается: 429 подставлен транспортом.
- Уже сохранённые данные прогона на месте, письмо наружу не уходит.
